## Project

**Nimbly** — maintenance management for interventions, preventive tasks, machine documents, and AI assistance. Stack: Next.js 14.2.35 (App Router), React 18, Firebase Firestore and Storage (no ORM), Firebase Auth, Tailwind CSS/Radix UI, React Context for shared state; single repo. ## Anti-patterns to avoid

- **Critical:** Users may write their own technician profile, including role and tenant fields used for authorization. Restrict those fields server-side before reusing RBAC. [firestore.rules](<D:/coding/1_Adigital heroes/custom/nimbly/firestore.rules>)
- Any authenticated user can write under `reports/{reportId}` in Storage rules. [storage.rules](<D:/coding/1_Adigital heroes/custom/nimbly/storage.rules>)
- Super-admin email lists and tenant fallback logic are duplicated; route handlers repeat auth/error handling. [config.ts](<D:/coding/1_Adigital heroes/custom/nimbly/src/lib/config.ts>), [firebase-admin.ts](<D:/coding/1_Adigital heroes/custom/nimbly/src/lib/firebase-admin.ts>), [data-provider.tsx](<D:/coding/1_Adigital heroes/custom/nimbly/src/components/data-provider.tsx>)
- Upload processing buffers files up to 300 MB and returns raw processing error messages. [upload/route.ts](<D:/coding/1_Adigital heroes/custom/nimbly/src/app/api/upload/route.ts>)
