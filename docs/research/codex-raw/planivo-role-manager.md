## Project

**Planivo** is a workforce management app for organizations, staff, scheduling, leave, training, and messaging. It is a single Vite 5.4/React 18.3 app, **not a Next.js project**. Stack: Supabase Postgres with SQL migrations and no ORM; Supabase Auth; Tailwind 3, shadcn/ui and Radix; TanStack Query plus React contexts. See [package.json](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/package.json>) and [index.html](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/index.html>). This was a read-only source audit.

## Anti-patterns to avoid

- Hardcoded development login credentials and a browser-generated, displayed “security OTP”: [Auth.tsx](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/src/pages/Auth.tsx>), [OTPVerificationDialog.tsx](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/src/components/auth/OTPVerificationDialog.tsx>).
- Password OTP is logged; rate-limit callers allow requests when the check errors: [send-password-otp](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/supabase/functions/send-password-otp/index.ts>), [admin-set-password](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/supabase/functions/admin-set-password/index.ts>).
- Privileged notification creation does not authorize the requested recipient; module-fetch failure grants full **core** permissions in the UI: [create-notification](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/supabase/functions/create-notification/index.ts>), [ModuleContext.tsx](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/src/contexts/ModuleContext.tsx>).
- Role lists differ across validation, dashboard, and sidebar; table declares sorting without implementing it: [validation.ts](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/src/utils/validation.ts>), [Dashboard.tsx](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/src/pages/Dashboard.tsx>), [DataTable.tsx](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/src/components/shared/DataTable.tsx>).
- Stripe webhook has no visible event-id deduplication; public chat storage deserves a privacy decision in a starter: [webhook](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/supabase/functions/stripe-webhook/index.ts>), [bucket migration](<D:/coding/1_Adigital heroes/custom/planivo-role-manager/supabase/migrations/20260104120000_add_chat_attachments_bucket.sql>).
